Große Dateien schnell schreiben, lesen und streamen

Eine API zum Verarbeiten von Daten über Speichergrenzen hinausStreamen von LogsSpringen in BinärdatenDekodieren im StreamSynchronisieren von Datenbanktabellen

Gigabytes pro Sekunde schreiben und streamen, jeden Offset in Mikrosekunden lesen: im Browser, unter Node.js und Bun, auf dem nativen Dateisystem, in OPFS oder im Speicher. Eine Hochleistungsschicht für binäre Datei-I/O-Streams unter Datenbanken, virtuellen Dateisystemen und Caches.

* Alles auf dieser Seite läuft in Ihrem Browser-Tab, ohne Backend-Server. Die Bibliothek ist isomorph: Dieselbe API läuft unter Node.js und Bun, und dieselben Vertragstests bestehen dort.

import { createOPFSStorage } from 'defuss-storage/opfs';
const storage = await createOPFSStorage({ name: 'my-app' });
const log = await storage.open('events.log', {
  create: true,
  writeBuffer: 1024 * 1024, // batch small appends
});
const bytes = new TextEncoder().encode('hello\n');
const { offset } = await log.append(bytes);
await log.readExactly(offset, bytes.byteLength);
await log.flush();

#Die Dateischicht unter Ihren Daten

Browser geben jeder Website ein privates Dateisystem, OPFS, aber nur als rohe Handles in Workern. defuss-storage macht daraus Dateien, auf denen eine Datenbank, ein virtuelles Dateisystem oder ein Cache aufbauen kann, und betreibt dieselben Dateien unter Node.js, Bun und im Speicher.

#Was Sie bekommen

Dateien, die ein Neuladen überstehen

OPFS speichert Bytes pro Origin auf der Festplatte. Der Adapter nutzt die synchronen Zugriffs-Handles von Dedicated Workers, in Chromium, Firefox und WebKit.

Ein Vertrag, drei Backends

Speicher, native Dateien und OPFS bestehen dieselben 33 Vertragsfälle: Gegen den Speicher getesteter Code läuft unverändert auf der Festplatte.

Kleine Schreibvorgänge, günstig gemacht

Ein optionaler Schreibpuffer bündelt kleine Anhänge: Abgewartete 4-KiB-Anhänge liefen in Chromium, Firefox und WebKit 8,7- bis 32-mal schneller.

Überlast wird abgelehnt, nicht gepuffert

Ein Aufruf über die Limits einer geöffneten Datei scheitert sofort mit QUEUE_FULL, bevor etwas kopiert wird. Im Überlasttest sank der Spitzenspeicher von 265 MB ohne diese Limits auf 134 MB mit ihnen.

Ein Besitzer pro Datei

Web Locks geben jeder Datei einen Besitzer über Worker und Tabs hinweg. Ein zweiter Öffner bekommt BUSY, bis der Besitzer schließt oder sein Worker endet.

Klein und ohne Abhängigkeiten

10,6 kB mit gzip für den OPFS-Einstieg, keine Laufzeitabhängigkeiten. ESM, CommonJS und TypeScript-Typen inklusive.

So funktioniert es

#Ein Aufruf, von Ihrem Code bis zur Festplatte

Jeder Adapter sitzt hinter demselben Handle: Es kopiert Ihre Eingabe, prüft sie gegen die Limits und führt Aufrufe der Reihe nach aus.

  1. 1

    Worker gestartet

    OPFS-Sync-Handles gibt es nur in Dedicated Workers: Der Worker besitzt die Dateien, Ihre Seite schickt ihm Nachrichten.

  2. 2

    Namensraum geöffnet

    createOPFSStorage({ name }) öffnet ein Verzeichnis; open() nimmt Web Lock und Handle der Datei.

  3. 3

    Quittungen geliefert

    Ein Anhängen liefert Offset und Länge, so indizieren Sie Datensätze, ohne nach der Größe zu fragen.

  4. 4

    Gesichert und geschlossen

    flush() sichert; close() arbeitet die Warteschlange ab und gibt den Lock frei.

    #Viele Anhänge auf einmal

    Senden Sie Anhänge ohne await: Jeder Aufruf, der in die Limits passt, wird angenommen. Senken Sie ein Limit unter die Last, und die übrigen Aufrufe scheitern sofort mit QUEUE_FULL, statt sich im Speicher zu stapeln.

    // limits come from createOPFSStorage({ maxPendingOperations, maxPendingWriteBytes })
    const calls = Array.from({ length: n }, () => file.append(chunk));
    const results = await Promise.allSettled(calls);
    // rejected: StorageError { code: 'QUEUE_FULL' }, nothing copied
    import { appendChunks } from 'defuss-storage';
    async function* chunks() {
      for (let i = 0; i < n; i++) yield chunk;
    }
    // as many appends in flight as the limits admit
    const inFlight = Math.min(maxPendingOperations, maxPendingWriteBytes / chunk.byteLength);
    for await (const receipt of appendChunks(file, chunks(), { inFlight })) count++;

    #Was die Optionen bringen

    Anhänge-Durchsatz pro Option und Laufzeit. In OPFS hilft der Schreibpuffer am meisten; inFlight hilft nativen Dateien.

    #Überlast, gemessen

    2.000 Anhänge zu je 64 KiB, ohne await in den Speicher-Adapter unter Node.js gesendet. 0.2.0 nahm 1.024 an und lehnte 976 sofort ab; sein ArrayBuffer-Speicher lag höchstens bei 134 MB, während 0.1.0 jeden Aufruf pufferte und 265 MB erreichte.

    #Zu groß für den Heap? Kein Problem.

    Der Speicher richtet sich nach der Chunk-Größe, nicht nach der Dateigröße. Jedes Handle nimmt nur eine begrenzte Menge ausstehender Schreibdaten an (standardmäßig 64 MiB) und lehnt den Rest mit QUEUE_FULL ab, statt ihn zu puffern, und appendChunks hält je einen Pull und ein Append offen. Beim Zurücklesen hält ein Stream einen Chunk, plus höchstens einen vorausgelesenen, während Ihr Code den letzten verarbeitet. Dateien, die ein Vielfaches des JavaScript-Heaps groß sind, laufen mit flachem Speicherverbrauch durch.

    • 512 MiBDatei geschrieben und zurückgestreamt
    • 32 MiBV8-Heap-Limit des Prozesses
    • 77 MBhöchster residenter Speicher

    Gemessen in einem Node.js-Prozess: in 1-MiB-Chunks geschrieben, mit SHA-256 zurückgestreamt. Balken maßstabsgetreu zur Datei.

    #Installieren, Datei öffnen

    Läuft unter Node.js ab 20.19, Bun und in jedem Browser mit OPFS.

    Betreiben Sie den Speicher in einem Dedicated Module Worker. Vite, webpack und esbuild bündeln ihn aus dieser new URL()-Form.

    import { createOPFSStorage } from 'defuss-storage/opfs';
    const storage = await createOPFSStorage({ name: 'notes' });
    const file = await storage.open('notes.log', { create: true });
    self.onmessage = async ({ data }) => {
      const bytes = new TextEncoder().encode(data + '\n');
      const receipt = await file.append(bytes);
      await file.flush();
      self.postMessage(receipt); // { offset, byteLength }
    };
    const worker = new Worker(
      new URL('./storage.worker.js', import.meta.url),
      { type: 'module' },
    );
    worker.onmessage = ({ data }) => console.log('stored at', data.offset);
    worker.postMessage('first note');

    Dieselben Aufrufe auf nativen Dateien. appendChunks kopiert einen Stream beliebiger Größe bei flachem Speicherverbrauch.

    import { createReadStream } from 'node:fs';
    import { appendChunks } from 'defuss-storage';
    import { createFileStorage } from 'defuss-storage/node';
    const storage = await createFileStorage('./data');
    const file = await storage.open('copy.bin', { create: true });
    try {
      const source = createReadStream('./input.bin', { highWaterMark: 64 * 1024 });
      for await (const { offset, byteLength } of appendChunks(file, source, { inFlight: 16 })) {
        // index records by offset here
      }
      await file.flush();
    } finally {
      await file.close();
    }

    API

    #Kleine API, große Wirkung auf die Performance

    Adapter erzeugen Handles; Handles erledigen das I/O. Die README beschreibt jede Invariante vollständig.

    AufrufWas er garantiert
    open(name, options)Scheitert an einer fehlenden Datei, außer mit create: true; kürzt nie eine vorhandene. Optionen: readOnly, exclusive, writeBuffer.
    append(bytes)Wählt das Dateiende und schreibt in einem eingereihten Schritt; liefert { offset, byteLength }.
    write(offset, bytes)Kopiert die Eingabe beim Aufruf oder übernimmt sie mit { transfer: true }. Beim Verlängern wird die Lücke mit Nullen gefüllt.
    readExactly(offset, length)Den ganzen Bereich oder UNEXPECTED_EOF. Nie ein verkapptes kurzes Lesen.
    readInto(offset, target)Füllt Ihren eigenen Puffer und gibt die Anzahl zurück, ohne zu allokieren.
    stream({ start, end, chunkSize })Async Iterable eigener Chunks, standardmäßig 64 KiB; liest voraus, während ein langsamer Verbraucher arbeitet.
    truncate(size)Kürzt oder verlängert mit Nullen.
    flush()Bittet das Backend zu sichern: ein File-Sync unter Node.js, ein Handle-Flush in OPFS.
    close()Arbeitet eingereihte Aufgaben ab, gibt den Besitz frei. Idempotent und wird immer angenommen.
    appendChunks(file, source)Hängt ein Async Iterable Chunk für Chunk an, mit bis zu inFlight gleichzeitigen Anhängen, und liefert Quittungen in Reihenfolge.

    #Fehler, auf die Sie reagieren können

    Jeder Betriebsfehler ist ein StorageError mit einem von zwölf Codes. Prüfen Sie den Code, nicht die Klasse: Er übersteht Modul- und Realm-Grenzen.

    • NOT_FOUND
    • ALREADY_EXISTS
    • BUSY
    • CLOSED
    • READ_ONLY
    • PERMISSION_DENIED
    • QUOTA_EXCEEDED
    • UNEXPECTED_EOF
    • UNSUPPORTED
    • ABORTED
    • QUEUE_FULL
    • IO_ERROR

      await storage.open('events.log');
